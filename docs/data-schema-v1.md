# 自治体データ・スキーマ1

状態：2026-10-07。[Issue #4](https://github.com/oukiito/gomimap/issues/4)のデータ基盤を実装。自治体ごとに1つのJSONを読み、区域・日程・回収サービスを判定する。現在同梱するデータは[自作のfixture](../data/datasets/fixtures/toshima-demo-v1.json)のみ。実データの公開、GPS・住所の入力画面、更新配信、通知・ウィジェット本体は未実装。

## 保存と識別

共通構造を自治体ごとに使う。自治体IDと区域／区分／施設／サービスIDを組にして識別し、異なる自治体の同じ区域IDを混同しない。`demo-toshima`は試験用の名前空間で、実地区の設定へ流用しない。コード体系と値は任意のペアとして保持し、未確認の自治体コードを作らない。

| ルートのフィールド | 意味 |
| --- | --- |
| `schemaVersion` | 整数の`1`。未知の版・未定義フィールドは読み込みを拒否 |
| `version` | 自治体別の不変のデータ版。同じ版を別内容で上書きしない |
| `kind` | `fixture`／`verified`。fixtureは読み込み側が明示許可したときだけ利用可能 |
| `publishedAt` | UTCの公開日時の宣言。取得・確認日時より後であることを確認 |
| `validPeriod` | 日程を使える開始日を含み、終了日を含まない期間 |
| `municipality` | ID、名称、公式HTTPS URL、`Asia/Tokyo`、任意のコード体系と値 |
| `sources` | 出典、取得・確認主体と日時、原文位置、利用条件、適用期間 |
| `areas` | 区域と住所条件の候補、有効期間、根拠 |
| `categories`／`items` | 自治体の区分と品目を分離。区分の定期収集対象、品目の特別な回収地図掲載対象を明示 |
| `baselines`／`exceptions` | 区域・区分ごとの通常日程と、取消／追加／振替／未確認の日付例外 |
| `facilities`／`services` | 建物・位置・公開性と、回収窓口／ボックス・受付時間・稼働状態を分離 |
| `acceptanceRules` | サービスと品目ごとの受入条件、有効期間、根拠 |

日付は厳密な`YYYY-MM-DD`、時刻は`HH:mm`、取得・確認・公開日時は秒までの`YYYY-MM-DDTHH:mm:ssZ`。不正な日付の繰り上がりは認めない。スキーマ1は日本の自治体だけを対象とし、瞬間からの日付変換はUTC+9で行う。端末のタイムゾーンや表示言語を日程の基準にしない。

JSONは2 MiBまで、各配列は最大10,000件。大きな自治体データの分割、署名／チェックサム、更新manifestは後続の配信設計で扱う。`DatasetSnapshot`はメモリ内の検証と切り替えを担当し、端末DB・ファイル保存やHTTP処理を実装したものではない。

## 住所条件

`addressSelectors`は条件グループの配列。同じグループ内は全て一致、グループ間はいずれかが一致する構造。条件は`field`、短い`question`と、次の演算子を持つ。

| 演算子 | 判定 |
| --- | --- |
| `isValue` | `values`の1値と一致 |
| `oneOf` | `values`のいずれかと一致 |
| `range` | `minimum`〜`maximum`の数値範囲。両端を含む |

入力なし・空の文字・異なる型・非有限数はunknown。確認できない入力を自動補完しない。住所条件の結果はmatched／needsInformation／needsConfirmation／ambiguous／unsupported。一致する区域が複数、または未回答で残る別候補がある場合は1番目を選ばない。根拠や区域の期限切れは、未対応住所と区別して確認が必要な状態にする。

このAPIは明示的な住所条件を評価するだけ。GPS、逆ジオコーディング、境界ポリゴンの照合、住所の正規化・別名検索、実地区の設定保存は未実装。fixtureを現在地へ対応付ける動作もない。

## 日程と不明状態

通常日程は、区域と定期収集区分のそれぞれに有効なbaselineを必要とする。`recurrences`の曜日は月曜1〜日曜7、`monthOccurrences`は月内の1〜5回目。空の`monthOccurrences`は毎週、空の`recurrences`は根拠付きの「定期収集なし」を明示する。

「baselineが存在しない」と「確認済みで収集なし」を区別する。同じ区域・区分で期間が重なるbaselineは拒否し、隣接期間の切替は終了日から次の版を適用する。同日に異なる締切が衝突した場合は、都合のよい時刻を選ばず確認が必要な状態へ戻す。

取消は指定区分だけを除去し、他の収集を残す。追加・振替は区分と締切を明示し、振替は元の日の取消と指定した対象日の追加をまとめて表す。対象日が年を跨ぐ場合も実際の年月日を持ち、前年の例外を次年度へコピーしない。同じ区域・区分・日付の矛盾する変更はJSON全体を拒否する。

出力は`collection`／`none`／`needsConfirmation`。未確認の日付例外は確認済み取消より優先する。データ・区域・根拠が期限外、通常日程が欠ける場合はneedsConfirmationで、日程カードは「収集予定の確認が必要」と公式リンクを表示する。他の有効な日・区域の判定は継続できる。

`DaySchedule.toJson()`は自治体・区域・データ版、ローカル日付、区分・原文名・締切、根拠、fixtureの印、不明理由を保持する。アプリの今日と地区確認プレビューはこの判定を使用済み。通知・ウィジェットもこの結果を使う計画で、OS側の予約・共有・表示は未実装。fixture・不明・収集なしは通常の種別通知の対象としない。

## 回収サービス

地図対象は`items.mapEligible`で明示する。通常のごみ・PET等や、利用世帯が決まる`householdCollection`は回収場所候補へ出さない。一般向けの`publicDropOff`について、品目別の受入条件を判定する。

条件結果はaccepted／rejected／unknown。状態・寸法・メーカー等に必要な回答が欠ける場合、受入可能としない。座標・受付時間・施設／サービスの根拠が不明、サービスの休止・未確認・期間外の場合は推奨しない。休止の終了を推測してactiveへ戻すこともない。住所の根拠を持つだけでは受入条件の根拠を持つことにならず、それぞれの参照を要求する。

受付窓口の営業時間は施設全体と分離。地図候補は後日の訪問にも使えるため、今閉まっているだけでは適合する場所を消さない。`openingAt`で開いている／閉まっている／不明を別に返し、開始時刻を含み終了時刻を含まない。日を跨ぐ受付窓・臨時の受付時間・仮移転の自動解決は未実装。

この判定の回収場所画面への接続はG09で行う。現在の画面は従来の架空2拠点を使い、実施設・受付時間・経路案内には接続していない。座標の数値範囲と精度の存在を検証するが、原文と座標の正確性や地図で十分な精度かを自動保証するものではない。

## 出典と公開検査

各住所・日程・場所・条件に`sourceIds`を付け、欠けたID・不正なHTTPS・重複ID・不正な期間・条件等を拒否する。verifiedには、確認済み・再配布可・fixtureでない・登録ID付きの根拠を要求する。

公開用CLIは対応する[出典登録簿](sources/toshima.md)の自治体ID、登録ID、URL、再配布状態、ライセンスとの一致も確認する。出典登録簿自体は既存のPython検査で確認する。この検査は**宣言の整合性**を確認する処理で、日程・受入条件が原文と一致することや法的な許可・人の承認を自動証明しない。重要な自治体情報は引き続き人が原文と照合して承認する。

```sh
# リポジトリ直下：出典メタデータを検証
python3 scripts/validate_sources.py

# app/から：製品JSONと対応する登録簿を検証
dart run tool/validate_dataset.dart ../data/datasets/<municipality-id>/<version>.json ../data/sources/<municipality>.json
```

公開URL・承認PR・配信用チェックサムを実際の更新手順と結び付ける処理、Cloudflareへの公開、端末の旧版復旧はG10／G11の継続作業。再利用条件が未確認の実資料をfixtureに置き換えて公開することはしない。

## 全国向けの拡張境界

schema1は一つのareaIdを軸に、区域×区分の日程を表す。品目・回収方式で異なる区域、部分的な確定、夜間の持ち出し窓は[全国対応設計](national-collection-matching.md)のCalendar v2／HomeCollectionProfileで別に定義する。schema1の未知キー拒否を緩めず、fixtureを実住所へ対応付けない。v2のcodec・移行・合成試験は未実装。
