## 範囲と残る確認

ユーザーの初回操作と、SDKからのプロセス／保存データ／一時ファイルの確認を区別する。端末のスクリーンショット、全画面・読み上げの直接観察はしていない。文字拡大、検索とAndroid戻る、通常の設定変更から再起動復帰、HTTP更新・オフライン・失敗復旧、通知・ウィジェット、iOSは継続する。

ネット接続の回答を待ち、通信失敗をアプリ固有の保存不具合と断定しない。DNS・VPN・証明書・端末の安全設定を勝手に変更したり、正規の取得を装うキャッシュを注入したりしていない。デバッグ接続と生ログはローカルの非公開領域へ分離し、認証値・端末識別子・他アプリのデータを公開しない。

UIの理由は[初回設定](../ux-initial-setup.md)と[更新 D01〜D06](../ux-data-refresh.md)に従う。GPS・実住所・実日程・実地図・通知・ウィジェットは未実装／未接続のまま。

## 続報：通常の更新・端末保存・オフライン操作

同日、本人から「普段のサイトはモバイル回線で開ける」「PixelのブラウザでmanifestのJSONが開けた」と報告を受けた。MacのIPv4／IPv6名前解決・HTTP200とPixelのシステム側の名前解決を確認。アプリのINTERNET権限は許可済み、データセーバーは無効だった。ネットワーク・DNS・VPN・証明書の設定は変更していない。

アプリだけをデータ消去なしで停止・起動したところ、通常の起動後更新で`files/datasets-demo/current.json`が生成された。デバッガーからの注入ではなく、アプリ本来のHTTPS取得・検証・保存の完了として確認した。

## 起動時の待ち時間

本人からFlutterの起動アイコンと速度の指摘を受け、同じPixel・同じアプリソース・同じ保存データで、Flutter公式の`--trace-startup`をdebug／profile各1回実行した。アプリコードは変更していない。

| 指標 | debug | profile |
| --- | ---: | ---: |
| エンジン開始→framework初期化 | 252.800 ms | 97.745 ms |
| エンジン開始→最初のフレーム構築 | 7,284.245 ms | 202.252 ms |
| エンジン開始→最初のフレーム描画 | 7,472.067 ms | 252.356 ms |

各1回・トレース有効の測定で、端末負荷・再インストール・キャッシュ条件を統制した統計比較ではない。タップから画面が見えるまでの全時間、OSの起動アニメーション時間、全利用者の起動時間とは区別する。debugのJIT／検査／トレースの影響もあり、releaseの速度をdebugの数値で断定しない。[Flutterの性能計測](https://docs.flutter.dev/perf/ui-performance)、[ビルドモード](https://docs.flutter.dev/testing/build-modes)。

profile APKのビルドと同じ署名での更新は成功。Pixelへprofile版を残し、地区Aと正規保存JSONの保持を再確認。本人から「たしかにちょっと早い」と体感の報告を受けた。署名鍵・ストア登録は変更せず、profileを一般公開版とは扱わない。今のFlutterアイコンはテンプレートのアイコンで、Androidの標準起動画面に表示される。[起動の設計 P01〜P04](../ux-startup.md)を参照。
