## 最終方針で置き換えた初期提案

- 文書化後のユーザー補足：地図は電池など専用の回収先を探す特別な品目向け。通常の燃やすごみや古紙・びん・かん等の収集は予定と分別案内で扱う。全てのごみ・資源の持込場所を網羅する地図にはしない。
- 回収場所の「一覧中心・外部地図のみ」は不採用。地図中心の画面を初回から提供し、経路案内は外部地図に渡す。
- ウィジェットの後日追加案は不採用。両OSの初回版に含める。
- 全データの日次取得案は変更。通常データは週次、お知らせのみ日次。データ公開は頻度に関係なく検証・承認後。
- 不確かな日の文言「収集予定を確認中」は不採用。利用者指定の「収集予定の確認が必要」を使う。

## 技術上の推奨案（採用・実装は未完了）

Flutterを基盤とし、地図描画は2026-10-06に`flutter_map`へ移行した。タイル配信元は未設定。OS固有ウィジェット、検証済みデータの静的配信、端末内での予定計算、Pythonによる取得・検証処理を候補とする。LLMは安価な画像・テキスト入力対応モデルを実データで比較する。[技術構成](architecture.md)を参照。

個々のライブラリ、バージョン、クラウド契約、実行時刻はPoCで確定する。製品の合意と技術サービスの契約完了を混同しない。

## 明示的に残す確認事項

| 項目 | 解決する段階 |
| --- | --- |
| 権利者表記、正式アプリ名、行動規範の常設非公開窓口 | ソースはoukiito/gomimapで公開済み。GPLの適用範囲と第三者通知を記録。追加する権利者表記は本人に確認し、gomimapは作業名のまま |
| 自治体情報・位置データの再利用条件、出典表示方法 | G02。抽出可能であることは再配布許可を意味しない |
| 地図・位置検索の契約条件、精度、API制限と利用量別費用 | G03 |
| APIモデルへの実際のアクセス可否と抽出精度 | G03／G10。候補選定のみで有料APIを実行していない |
| 独立監視サービス、通知先、復旧担当者 | G10。運用を有効化する前に登録 |
| 試験端末、協力者、ストア開発者アカウント | G12。存在や確保済みを仮定しない |
| 最低対応OS、公開日、利用規模 | 技術検証・試用段階で確定。期限の合意はない |

## 変更方法

後の変更はIssueに目的と影響を書き、該当仕様と本書を同じPRで修正する。過去案を復活させる場合も、新しい決定として理由を記録する。
