# 起動時の表示・性能の理由

状態：2026-10-08。[Issue #3](https://github.com/oukiito/gomimap/issues/3)のPixel確認で起動アイコンと待ち時間の指摘を受けた。[測定結果](work/2026-10-08-pixel-runtime.md)はdebug／profile各1回。現状と今後の判断を分ける設計図。

| ID | 利用場面・動作と理由 | 現状・保持・失敗 | 確認 |
| --- | --- | --- | --- |
| P01 | 朝は地区と今日の内容を判断できる最初の画面へ。空画面を先に描いて指標だけを速く見せない | 設定と検証済みデータを読んで通常の初期画面へ。未確定・期限外を収集なしにしない。起動前の読込は必要な部分へ絞る改善候補 | 初回／保存済み／破損・期限外／未設定と、意味のある最初の画面。各段階の時間を測定 |
| P02 | 保存済み予定を通信待ちなしで使い、更新は初期表示後。弱い電波でも朝の判断を始められる | 実装済み。[D01〜D06](ux-data-refresh.md)に従い、更新で地区・タブを変えない。別の用件の地図等を起動の待ち条件に追加しない | 実機の取得・保存、本人のオフライン操作、ネットなしの画面試験 |
| P03 | 製品の性能は実機のprofile／release相当で判断。開発時のJIT・検査が速度判断を歪めないため | 同じ署名でprofileへ更新し、地区・データ保持を確認。profileは測定向け。画面・戻るは通常と同じ | モード・試行数・端末・指標の始終点を記録。単発測定を全端末の保証にしない |
| P04 | Androidの標準起動画面は開くアプリを識別。説明・宣伝・固定秒数の待ち演出を追加しない | 現在はFlutterのテンプレートアイコン。アプリ用アイコンの制作・置換は別作業。初期画面が準備できたら進む | コールド／ウォーム起動、明暗、対応OSで確認。アイコン置換だけで速度改善と主張しない |

Android12以降はOSの標準起動画面が使われ、標準ではアプリアイコンを表示する。[Android公式](https://developer.android.com/develop/ui/views/launch/splash-screen)。現在のテーマに独自の固定待ち時間は設定していない。アイコンを変える際は、ランチャー・起動画面・将来のウィジェット／通知との識別の一貫性と権利を確認する。

今回のprofile初回描画は252.356 msで、debugの7,472.067 msより短かった。コード最適化・アイコン置換はこの確認では実施していない。起動前の設定・同梱・保存データの読込とJSON検証の重複は今後の測定候補。検証・地区確認を省いて速度を得る変更はしない。大きい自治体データ・低速端末で改めて測り、優先度を決める。
