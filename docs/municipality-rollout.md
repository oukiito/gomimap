# 自治体の導入順位と住宅照合の調査条件

2026-10-10。[Issue #71](https://github.com/oukiito/gomimap/issues/71)。利用者指定：人口または外国籍住民が多い自治体を優先し、住宅とごみ収集区分の対応は詳細調査の後に実装する。本書は導入と実装の作業ルールで、全国順位表・調査完了・自治体公開の宣言ではない。

## 導入順位

豊島区は合意済みの先行検証地域として継続する。全国順位の1位を意味しない。以後の導入候補は、次の二つの順位を同じ統計時点・単位で持つ。

| 方式 | 比較順 |
| --- | --- |
| 外国籍住民数を優先 | 外国人住民の人数の降順 → 総人口の降順 → 自治体コードの昇順 |
| 総人口を優先 | 総人口の降順 → 外国人住民の人数の降順 → 自治体コードの昇順 |

主方式は利用者へ確認中。回答までの調査・候補整理は外国籍住民数優先を暫定案とし、総人口順位も併記する。分別に不慣れな住民に多言語で届ける目的に合うという推奨であり、本人がその方式を明示選択したとは記録しない。回答に合わせて切り替えられるようにする。具体的な順位は統計の原数値と注記を検査してから確定し、回答がなくても統計準備と詳細調査は進める。

人数を使い、外国人比率へ黙って置き換えない。外国籍であることから、日本語能力・情報リテラシー・分別知識を推測しない。この人数は利用者に届けられる規模の指標であり、個人の属性判定には使わない。

## 統計の揃え方

第一候補は、総務省「住民基本台帳に基づく人口、人口動態及び世帯数調査」の同一年の市区町村別「総計」と「外国人住民」。2026-10-10に[e-Statの2026年一覧](https://www.e-stat.go.jp/stat-search/files?cycle=7&layout=datalist&month=0&result_back=1&tclass1=000001039601&tclass2val=0&toukei=00200241&tstat=000001039591&year=20260)で表26-03／26-11、公開日2026-07-29を確認した。ここで確認したのは表の存在・名称・公開日であり、数値を読み込んだ全国順位表はまだ作成していない。

- 表内の人口基準日・外国人住民の定義・注記を確認し、公開日を人口基準日にしない。総計は日本人のみの表と取り違えない。
- 国勢調査、人口推計、住民基本台帳の人数を混ぜない。「人口移動報告」の転入者数や在留外国人統計の別定義も、そのまま代用しない。
- 市町村と東京都の特別区を全国比較の基本単位にする。政令市は市全体で順位を持ち、行政区は市内の段階導入の内訳にする。市計＋行政区、特別区部計＋各特別区を二重計上しない。
- 一部の区だけを公開した場合、市全人口を対応人口と表示しない。市内の順序も同じ主指標を使い、部分対応の範囲を別に記録する。
- 自治体コードを文字列で照合し、名称の似た地域を結合しない。合併・区割り変更・統計の訂正を記録する。
- 欠測・秘匿・注記記号は0に変換しない。必要な値がない自治体は順位保留とし、理由を残す。
- 年次更新・訂正公開・次の導入波の確定時に再確認する。進行中の作業を統計更新だけで自動中断せず、順位変更の適用時点を記録する。

順位表には、方式／版・人口基準日・統計名／表番号／URL・取得日／hash・自治体コード／地理レベル・総人口／外国人住民数・二つの順位・調査状態・導入範囲・保留理由を持たせる。原数値と除外／集計規則を再現できる形で保存してから順位を採用する。

## 優先度と実装可能性は別

調査の着手・作業配分は採用した人数順位を基本とする。資料が取りやすいことを、人口の代わりの順位指標にしない。一方、順位が高くても根拠不足の住宅照合を公開しない。

上位が未調査・矛盾・利用条件未確認なら、その順位と保留理由を残す。次の自治体を並行調査し、開始／公開条件を満たした自治体を先に進める場合は、需要順位と実際の導入順・理由を別々に記録する。簡単な自治体だけを選び直して上位の課題を消さない。

札幌・横浜・福岡等の異なる方式を調べることは、共通設計の反例確認であり、それだけで導入順位を上げない。豊島区の試行と代表方式の調査は、全国順位とは役割を分ける。

## 詳細調査を終えるまで実装しない範囲

この条件は住宅の対応付け・地域設定・新自治体の取込、及びそれに依存する製品Calendar／HomeCollectionProfile／GPS照合の実装へ適用する。fixtureやmockという名前にして製品ロジックを先行させない。資料比較や表現の可否を調べる使い捨ての調査PoCは可能だが、その成功を製品実装の承認にしない。無関係の不具合修正は通常の開発規則で進められる。

各自治体は[調査票ひな型](municipal-research/TEMPLATE.md)で独立した記録を作る。対象に申告した区域・種類・方式の全てについて、以下を揃える。

| ID | 実装前に調べるもの | 必須の成果物・判断 |
| --- | --- | --- |
| MR01 | 実施主体・対象範囲 | 市／区／組合／自治会／管理者の役割、家庭用／事業用、今回扱う区域・種類と除外範囲 |
| MR02 | 公式資料と版 | 現行リンク、原文位置、更新日・取得日・適用日・年度の区別、多言語版／旧版との矛盾、取得・保管・加工・送信・配布条件 |
| MR03 | 何を基準に区域が決まるか | 住宅住所、実際の排出場所、所属団体、カレンダー番号、建物等のどれか。住居表示と地番、番と号、道路沿い／反対側・除外・境界 |
| MR04 | 種類・回収方式別の対応 | 確認条件→stream→assignment→area→calendarの根拠付き対応表。方式間の違い、正当な重なり、同方式内の競合・穴・未対応 |
| MR05 | 日程・時間・改定 | 通常周期、月内回数と隔週の違い、年末年始／臨時例外、夜間・持ち出し日・終了時刻、区域分割／統合と適用日 |
| MR06 | GPS・住所データで解ける限界 | 地理データの粒度・精度・利用条件。自動候補、追加質問、番号等の本人選択、公式照会に分けた対応能力表。最寄り集積所を選ばない |
| MR07 | 利用者の設定手順 | 必要な質問・文言と理由、未回答／分からない、部分設定、戻る／取消、後の変更と再確認。全言語・文字拡大・読み上げ・48pxの確認計画 |
| MR08 | 独立した期待値 | 下記の原文照合ケースと人工fixture。抽出コード自身の出力を正解として使わない。出典・条件・期待結果・確認者／日・未解決を残す |
| MR09 | 継続運用 | 変更の発見先、根拠の有効期限、更新で再確認が必要な条件、対応する問い合わせ先と保留手順 |

## 正解ケースと反例

対象範囲の公式の対応行・例外を一覧化し、各行が対応表へ反映されたかを突合する。少数の住所で動いたことを自治体全域の合格にしない。少なくとも、存在する各条件型・例外型に対して次のケースを用意する。

- 通常の一致、同じ丁目内の分岐、番／号の境界値とその前後、道路沿い／以外、除外対象と非対象。
- 未回答・曖昧な原文・誤記・複数候補・該当なし。未回答の否定を真にしない。
- 別の町で同じ数字、住所体系違い、近いが利用対象外の集積所、職場のGPS、自宅と実際の排出場所の違い。
- 品目ごとに区域が異なる場合、通常収集と地域回収、確定済みと未確認・未対応が混在する場合。
- 日付／年度境界、夜間の翌日0時、区域改定前後、保存中のデータ版変更・取消・再開。

期待値は原文の該当行・注記と対にし、別の読取経路で照合する。AI二者の一致だけで原文の意味や利用許可が証明されたとはしない。実資料に基づく照合と人工fixtureの役割を分け、人工データだけで実住宅の正確性を合格にしない。再配布不可の原文・住所・個人宅の写真を公開テストへコピーせず、必要な私有照合も保管条件を確認してから行う。

母数は実住宅の全戸検証数ではなく、調査対象の対応行・条件型・例外型・期待値ケース数として報告する。未読・未対応・矛盾の件数と範囲も記録し、「誤り0件だから全国正確」とは書かない。

## 開始と公開の判定

| 状態 | 意味と次へ進む条件 |
| --- | --- |
| 調査中 | 収集資料・範囲・不足を記録。住宅照合の本体実装は開始しない |
| 調査済み | MR01〜09が対象範囲について埋まり、対応表・正解／反例・資料間の矛盾処理が記録済み。重大な未解決がない |
| 設計確認済み | 型／codec・状態遷移・UI理由・失敗／復旧・受け入れ条件が調査結果と一致し、レビュー済み。ここで実装を開始できる |
| 実装検証済み | 決めた期待値とUI／保存／通知・投影の確認が成功。調査範囲の変更時は再調査 |
| 公開可能 | 原文と利用条件の必要な人の確認、公開範囲・運用・実機／利用者の条件を満たした別判断。CI／AIレビューだけで公開可としない |

調査済みは資料を集めた状態ではない。対象範囲の重要な曖昧さがあれば調査中へ戻す。部分導入は範囲と除外理由を明記し、その範囲のMR項目を満たす。既存の未対応地域や不明な方式を、条件を通すために対象外へ言い換えない。

調査票と設計のレビュー記録・Issue・採用commitを実装PRへリンクする。ユーザーの今回の指示は事前調査の強化であり、各変更で同じ許可を聞き直すことではない。通常のコード実装は条件を満たせば進められる。外部問い合わせ送信、個別資料の利用許可、実データの原文承認は既存ルールどおり別に確認する。

豊島区も例外にせず、[調査台帳](municipal-research/toshima.md)は調査中。これまでの構造比較・fixture・設計書だけで調査済みや住宅照合の実装可能とは扱わない。
