# Androidホーム画面ウィジェット

関連：[Issue #7](https://github.com/oukiito/gomimap/issues/7)、UX02・10、S14、B13〜20。[初回設定](ux-initial-setup.md)のAndroid部分を実装。自作fixtureのみで、実際のごみ出しには使用できない。iOSウィジェットは未実装。

## 表示・操作・理由

| ID | 要素・動作 | 利用場面と理由 | 保持・戻る・失敗と確認 |
| --- | --- | --- | --- |
| W01 | 日付・曜日を上部で明示 | 朝、いつの予定かを確認。OSの更新遅延でも対象日を照合でき、相対語だけで現在日と誤認しにくい | 日本の暦日。時計・日付・タイムゾーン変更と境界を試験。厳密な0時更新は保証しない |
| W02 | 保存した地区を日付の下に14spで表示 | 家の地区と設定ミスを確認する | 地区は追加時に再入力しない。変更・取消・未設定を区別。別地区の投影なら確認必要 |
| W03 | 開発用サンプルの表示 | 架空日程を本当の収集と誤認しない | 全言語で短い表示。配信データも架空。実データ導入時にkindとの対応を見直す |
| W04 | 種類を通常24sp・小型20sp、締切を表示 | ごみの種類と出す時刻をすぐ判断する | 同一締切はW18でまとめ、異なる締切は種類ごと。複数区分を落とさない。色・アイコンだけで判定しない。不明・収集なしは時刻を断定しない |
| W05 | 予定部分を縦スクロール可能にする | 長い訳・文字拡大でも全ての区分を読める | 日付は固定。2×2の小型では地区・サンプルも本文と一緒にスクロールし、大型では地区を固定。行数で切らず48dp以上の行操作。最小サイズと200%を試験 |
| W06 | 次の予定を補助表示 | 主表示の後にも予定があることが分かる | 次の未確定日を飛ばして後日の収集を確定次回としない。投影範囲外の次回は推測しない |
| W07 | タップでアプリの今日へ | 詳しい出し方・不確かな日の公式情報へ進める | 開いている詳細を閉じて今日へ。検索入力は保持。地区未設定なら初回設定へ。外部URLを勝手に開かない |

| W09 | AndroidのOS追加要求へ渡す | 利用者の選択後は地区・言語を再入力せず追加できる | 要求受理と配置済みを区別。OS確認を省略しない。取消で初回を止めず、設定から再試行 |
| W10 | 非対応・失敗時にホーム画面からの短い追加手順 | 一つの追加方法が使えなくても用件を終えられる | 動かない追加ボタンを置かない。初回はスキップ、設定は戻る。保存失敗を成功にしない |
| W11 | 設定から追加状況・再追加を表示 | 初回スキップ・削除後も追加できる | OSの実IDで配置を確認。単なる要求で追加済みと表示しない。通常起動の提案を復活させない |
| W12 | 本体の判定から日付別に投影し、端末保存 | アプリ未起動・オフラインでも同じ地区・版の情報を示す | 新しい独自収集ルールをネイティブで作らない。35日を超えたら確認必要。破損・別地区・別の保存版を確認必要にする |

| W13 | 締切前は今日の未締切区分、全て締切後は次の収集／確認日を主表示 | 午後に朝の予定を大きく表示しても準備の判断に役立たない。一律10時でなくJSONの区分別締切で判断 | 締切ちょうどから切替。回収済みとは断定しない。不確かな今日は終わったと推測せず確認を維持。未来の未確定日を飛ばさない |
| W14 | 今日／明日／次回と絶対日付をセットで表示 | 次の予定を今日と誤読しない。収集なしの日を飛ばしてもいつ出すか分かる | 投影内に次の予定がない場合は確認必要。範囲外・破損時に推測しない |

| W16 | 締切・日本0時・前面復帰で再評価 | 開きっぱなしでも日付・締切に追従。検索中に用件を失わせない | 本体タイマー、ウィジェット時間帯投影の通常アラーム。OSの遅延は残り、正確な更新到達を保証しない |

最小／初期サイズは2×2を希望し、縦横にリサイズ可能。ランチャーごとにセル寸法は異なる。既存配置の大きさはOSが保持するため、更新だけで強制的に縮めない。小型では次々回を省き、対象日・地区・種類・締切を優先する。長い訳や200%文字では本文をスクロールして読める。

| W17 | 本体の主カード内の公式確認ボタンを白色で表示 | 不明な日程で次の操作を見つける。濃い緑の背景に同系色のボタン文字は読みにくい | 48px以上の操作領域を保ち、文字でも目的を示す。実画面と読み上げラベルを確認 |
| W18 | 共通の締切を1行で表示し、種類の重複を省く | 2×2で種類を繰り返すと締切が下へ隠れ、朝に出す時刻を読めない | 種類は主表示に全て残す。異なる締切は種類と時刻をそれぞれ残す。共通／異なる締切のDart試験、実寸の行測定と日英PNGで確認。画面・地区・戻る動作は変更しない |
| W19 | 初回提案とウィジェット名を「ごみの予定」とする | 締切後は次回も表示するため「今日のごみ」だけでは対象日を誤解する | 既存の追加・スキップ・再追加を維持。全対応言語の提案文を予定の表現へ更新。日付と今日／明日／次回の表示で照合する |
| W20 | 本体とウィジェット全体を保存した言語で更新 | 日本の分別に不慣れな住民が選択言語で対象日まで読める必要がある | 描画内容ごとに一覧アダプターを識別し、古いヘッダーを再適用する別の一覧更新通知を送らない。配置・地区・日程は保持。日→英→日を実画面で確認し、日付／言語で識別子が変わることもSDKで試験 |

## 実装の境界

`ScheduleCalendar`／`DaySchedule`から35日分の区分別締切による時間帯と全10言語の表示をDartで作る。Androidは`files/home-widget/current.json`へ候補をflush・同一ディレクトリrenameして保存し、日本の現在日付・分の時間帯を選ぶ。512KiBを上限として版・地区・日付範囲・状態・行数を検査する。保存済みの自治体JSONの版・hashとの整合を確認し、別版・別地区を使わない。期限切れは投影生成時の日程判定と投影の終了日の両方で保護する。

投影のschemaVersionは2。Dartの`scheduleFocus`で未締切区分・未来の最初の収集／未確定日を選び、Androidは時間帯の選択だけを行う。元の全日程は変更しない。投影終了間際に未来を探せなくなった場合も「収集なし」と断定しない。

言語はアプリの保存設定、未選択なら対応する端末言語を使う。ネイティブの復旧表示・選択画面のラベルもARBから生成する。新しい外部パッケージは追加せず、Android標準RemoteViews・AppWidgetProvider・AlarmManager・Flutter MethodChannelを使う。

一覧のアダプターURIには描画内容のSHA-256を含める。同じ描画は同じURI、言語・地区・日付・予定が変われば別のURIとし、全体のRemoteViews更新で再読込する。URIは端末内の識別用で外部へ送信しない。別の一覧変更通知を重ねると旧ヘッダーが残る問題を専用エミュレータで再現したため、通知を重ねない。

OSの30分定期更新と、次の区分別締切または日本0時に対する幅10分の通常アラーム、日付・時刻・言語・起動等のイベントで更新する。正確なアラーム権限は要求しない。Doze・省電力・ランチャー・強制停止で更新は遅延しうる。日付を表示し、厳密な時刻や更新到達を保証しない。アプリの前面復帰・地区／言語／データ変更でも投影を更新する。

追加は[AndroidのrequestPinAppWidget](https://developer.android.com/reference/android/appwidget/AppWidgetManager)へ渡し、OSの利用者確認が必要。返値trueは配置完了ではない。[標準ウィジェット](https://developer.android.com/develop/ui/views/appwidgets/overview)、[更新と追加](https://developer.android.com/develop/ui/views/appwidgets/advanced)、[アラームの制約](https://developer.android.com/develop/background-work/services/alarms)を確認した。アプリの起動日付も実際の日本日付へ合わせ、固定の2026-10-05は試験の明示的な注入に限定する。

## 確認方法

共有予定の不明・範囲外・複数区分・期限、初回回答・再起動・失敗・全言語／文字200%はDart試験。日付選択・日本0時・月年境界・別地区・破損・翻訳・ネイティブ行の拡大はAndroid SDK標準Instrumentationで検証する。これはランチャーでの実際の配置・見た目とは別。

PixelでOS追加確認、実ID、予定表示、タップ、地区／言語の反映、オフラインを確認し、[作業記録](work/README.md)へ確認主体と未確認項目を残す。日付変更の判定は端末時計を勝手に変えず、試験の入力日付で検証する。iOS・他ランチャー・他端末・実データ・通知は本実装の成功に含めない。
