# プロダクト仕様

状態：製品方針は合意済み。細部の画面配置・性能目標は実装用の提案。開発用サンプルによるローカルPoCを作成済み。製品版は未完成。

## 目的と対象

豊島区で通常の家庭ごみを出す人が、今日出すものと準備を迷わず確認できる。電池・小型家電・蛍光灯など、専用の回収先を探す特別な品目は、位置関係が分かる地図で探せる。年齢・性別にかかわらず、スマホや分別用語に詳しくない人も使える。

日本語・英語・中国語（簡体字／繁体字）・韓国語・ベトナム語・ネパール語・ポルトガル語・スペイン語・フィリピノ語（タガログ語）に対応する。右上の地球アイコンから言語を選び、端末に保存する。初回は端末の対応言語を使用し、非対応言語のみの場合は日本語にする。切り替えても地域・画面・品目の選択を維持する。公式リンク先は翻訳せず、日本語以外の表示では日本語ページであることを示す。「さんあ〜る」にも予定・通知・検索・一部地域の写真機能があるため、機能の有無だけで優位と主張しない。設定の完了率、今日の予定の読み取り、条件に合う持込先の発見を検証する。

## 初回リリース

| 提供する | 後の段階で検討する |
| --- | --- |
| 今日・明日・今後の収集予定、分別の注意 | 複数の自宅、家族同期、事業ごみ |
| 当日／前日の通知、ホーム画面ウィジェット | ロック画面用ウィジェット、出した記録 |
| 品名・別名による分別検索、粗大ごみ条件と公式窓口 | 写真AI、粗大ごみの申込・決済代行 |
| 電池など特別な品目で絞る回収拠点の地図、ピンの詳細、外部経路案内 | 店舗の独自回収の広域収集、投稿型拠点情報 |
| 検証済みデータのオフライン利用 | 背景地図のオフラインダウンロード |

## 初期設定

1. 「自宅のごみの日を設定する」と目的を説明する。
2. 「現在地から探す」「住所から選ぶ」を同じ画面に置く。位置情報の許可は前者を選んだ時点で求める。
3. 候補地域を示す。町丁目で収集日が確定しない地域のみ、番地や通り沿いの条件を追加確認する。
4. 自宅の地域・収集予定の例を確認して保存する。GPS誤差、境界、職場での設定などで自動確定しない。
5. 初回だけ、保存した地区の予定を示すウィジェットの追加を提案する。プレビューと「追加する／追加方法を見る」「スキップ」を置く。アプリを開かず今日のごみを確認する方法を知らせるため。
6. 通知の説明と時刻を提示。有効化を選んだ場合にOSの許可を求める。「あとで」も用意する。

位置・地区確認・後からの変更・OS別のウィジェット追加・一度だけの案内は[初回設定の設計図](ux-initial-setup.md)に、各UI・操作の理由と共に記録する。

住所・座標を公表しない。端末には必要な収集区域IDを基本として保存し、不要な精密位置は保持しない。逆ジオコーディングを使う場合の第三者への位置送信は、採用方式に合わせて説明する。地図を動かしたり旅行したりしても、自宅の収集区域は変えない。

位置を確定できない場合は住所選択へ戻れる。豊島区外は未対応と明示し、豊島区のルールを流用しない。建物独自のルールは管理者への確認を案内し、通知を止められるようにする。

## 画面構成

利用者像は[ペルソナ](personas.md)、全画面・主要操作・画面遷移の理由と検証方法は[UI設計](ux-design.md)に記録する。UI変更時は利用者の場面・目的を示し、迷いや誤案内につながる箇所を指摘・修正する。理由が未検証の場合は仮説と明記する。

画面の文言は、ごみ出しの判断・操作に必要な情報に絞る。「今日のごみ、ひと目で。」のような宣伝文句や、情報を増やさない見出しは置かない。地域・日付・収集内容を優先する。

下部の主要導線は「今日」「分別を調べる」「資源回収場所」の3つ。名称変更後も、地図の対象は電池などの特別な品目に限定する。設定と言語切り替えは右上に置く。

各タブの画面上部に、選択中の「収集地区：…」を常時表示する。本文より控えめな文字とし、拡大・折り返しに対応する。スクロールの外に置き、タップで変更できる広さを確保する。設定からも変更でき、詳細には対象地区を示す。どの地区の日程・分別を見ているか分かり、設定ミスを発見・修正できるため。未設定・候補を保存済みの地区として表示しない。

### 今日

- 日付・曜日、今日のごみ、出す時刻、最低限の準備を大きく表示。地区は上部の共通表示で控えめに示し、本文へ重複して大きく表示しない。
- 明日と次回の予定を続けて表示し、先の予定はカレンダーで確認できる。
- 同日に複数の区分がある場合は全て表示。長い名前を重要部分ごと隠さない。
- 収集なしの場合は「今日は収集なし」と次回の予定を示す。
- 期限を過ぎても収集済みとは断定しない。締切時刻は収集車の到着時刻ではない。
- 未確定の日は **「収集予定の確認が必要」** と公式情報へのボタンを表示する。
- 取得済みの有効な予定は通信なしで使える。最終確認日とデータの有効範囲を確認できる。

### 調べる

普段使う品名・別名で検索する。かな表記や「缶／かん」などの違いを吸収する。検索結果は区分名だけでなく、次の収集日・準備・必要なら回収場所への導線を含む。

粗大ごみは品物と寸法などを確認し、自治体の条件・除外品に照合して申込先へ案内する。例外を確認せず「30cm以上なら全て粗大ごみ」のような全国共通判定にしない。該当ルールがない場合は推測せず公式情報へ案内する。

### 特別な品目の回収場所：地図が主役

地図は電池・小型家電・蛍光灯など、専用の回収先を探す品目に限定する。通常の燃やすごみ・燃やさないごみや、古紙・びん・かん・ペットボトル等の収集場所は対象外で、ホームの予定・通知・分別検索で案内する。「特別な品目」はアプリの案内上の区分であり、自治体の正式な分別区分名や危険物の総称ではない。具体的な掲載品目は自治体の公式情報と受入条件を確認して登録する。

電池など地図対象の品目に通常収集で出せる選択肢もある場合は、分別検索からその日程・条件も案内する。必ず持ち込む必要があるとは表示しない。

- 地図を画面の中心に表示し、上部に「電池」「小型家電」など絵と文字の品目選択を置く。
- 初期中心は保存した地域。現在地表示は利用者が選んだときだけ使う。自宅住所は他者と共有しない。
- 品目未選択時も地図対象の特別な品目に対応する掲載拠点だけを概観できる。「この品物を出せる」とは表示しない。
- 品目の受入可否に関係する場合だけ、種類・寸法・状態等を確認。分からない選択肢を残す。
- 条件が合う拠点を表示する。未確認と休止は明確に区別し、推薦対象から外す。確認済みの適合拠点がない場合は「確認済みの回収場所がありません」と広域検索・公式検索への導線を出す。掲載範囲内に未確認・休止拠点がある場合は、その状態も別に示し、拠点が存在しないとは断定しない。
- 拠点が密集したらまとめ、同一施設内の複数ボックスは施設ピンから選べる。
- ピン選択で小さな下部カードを表示。施設名、受付時間、条件、「行き方」を先に示し、広げると詳細を読める。
- 詳細には窓口・ボックスの階や場所、準備、対象者、休止期間、公式情報、電話を表示。
- 受付時間不明なら「受付時間は要確認」。通常営業時間から算出した表示を現地のリアルタイム状況として断定しない。
- 地図操作が難しい人は一覧へ切り替え可能。一覧は代替導線であり主画面ではない。
- 地図の通信障害時も、取得済みの拠点名・住所・条件を一覧で読める。経路は外部地図アプリで開く。

家庭用集積所を公共の持込先として表示しない。区境を越えた近隣拠点は、利用資格を満たすと確認できる場合だけ案内できる構造にする。初回の掲載データは豊島区に限定する。

## 通知

当日6時を初期候補とし、明示的に有効化する。前夜20時は任意。時刻・対象区分を変更でき、ごみのない日は送らない。前夜通知は翌朝の準備のためであり、夜間のごみ出しを勧める文面にしない。

不確かな日の種別通知は予約しない。新データ受信時は取り消し・再予約を行い、変更前の通知と重複させない。自宅変更、時計変更、OS再起動、権限取消、長期間未起動を試験対象にする。

通常の予定は端末のローカル通知を第一候補とする。6時ちょうどの到達や、端末がデータを受信していない間の臨時変更の反映は保証しない。権限・省電力・OS制約を実機で調べ、設定状態を確認できる画面を用意する。

## ウィジェット

両OSとも初回はホーム画面用1種類。地区、日付・曜日、今日の全区分、締切を表示。収集なしなら次回、未確定なら指定の確認文言を示す。タップで該当日の詳細へ移動する。初回設定で追加を提案するが、スキップでき、追加自体を利用開始の必須条件にはしない。通常起動では勧め直さず、後から設定で追加できる。

利用者が追加を選んだら、自宅地区・言語・表示データを引き継ぎ、対応AndroidではOSの追加要求へ進む。iPhone・非対応Androidでは短い追加手順を示す。OS上の操作や確認が必要な場合は利用者が行う。追加要求が通ったことや手順を読んだことだけで「追加済み」と表示しない。詳細と公式根拠は初回設定の設計図を参照する。

表示データには対象日と有効期限を含める。日付を跨いだ表示のままでも「今日」と誤認させない。OSが更新時刻を制御するので、毎分のカウントダウンを設けず、将来日付の表示予定を前もって渡す。文字拡大・複数区分を収めるサイズをPoCで決める。

## アクセシビリティと公開条件

文字とアイコンを併用し、色のみで区分しない。読み上げ順・操作名、文字拡大時の折返し、十分なタップ領域を両OSで確認する。地図ピンの内容は読み上げ可能な一覧でも取得できる。

一般公開には以下を満たす。試験記録は[開発計画](roadmap.md)のG12に残す。

1. 豊島区の住所例外、月2回の曜日、年末年始、有効日変更を検証する。
2. iOS／Android実機で通知・日付変更・ウィジェット・オフライン表示を確認する。
3. 操作に不慣れな人を含む5人程度で、初期設定、今日のごみ確認、品物に合う持込先と条件の発見を試す。手助けが必要だった箇所を修正し再確認する。
4. 不確かな日・拠点の扱い、公式情報への導線が機能する。
5. 公開するデータの利用条件を確認する。

協力者を確保できない場合は利用者検証を未完了と記録し、試用版を継続する。未実施を合格扱いにしない。
