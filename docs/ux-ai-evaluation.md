# AIによるペルソナ想定の模擬利用評価

状態：2026-10-08。AIが実画面を操作して問題候補を探す手順。[ペルソナ](personas.md)と[人による試験U1〜U7](ux-design.md#利用者試験)に対応付ける。AIの操作成功を、人にも使いやすいことや一般利用者の成功率の証明にしない。実機・人の観察・翻訳話者確認は別に実施する。

## 条件と記録

ペルソナは性別・国籍だけで作らず、言語、分別経験、操作経験、文字サイズ、用件と利用場面を指定する。初見の独立評価をする場合、設計書・ソースコード・正解の導線を操作役へ渡さず、画面と用件だけを渡す。開発担当が評価する場合は、設計や実装を知っていることを明記する。AIが日本語を解釈できる等、ペルソナ制約を忠実に再現できる保証はない。

| 条件ID | 想定する場面 | 用件 |
| --- | --- | --- |
| A1／P1 | 日本語で使う家庭のごみ出し担当者。朝は操作を減らしたい | 指定されたサンプル地区を設定し、表示例の今日の区分と締切、不明の日を確認 |
| A2／P2 | スマホには慣れているが日本の行政用語に不慣れ。英語で使う転入者 | 電池を検索し、充電池の案内から回収場所へ進む。説明へ戻って確認する |
| A3／P1・P2の操作条件 | ドラッグや外側タップを閉じる操作だと気付きにくい人を想定 | 品物・拠点・設定を開き、画面内の操作で閉じる。直接回収場所へ入って品目を選ぶ |

対象は試作の操作。実地区、実際の収集時刻、訪問できる拠点の正確性、OSウィジェット・通知は未実装として扱い、その用件を成功と記録しない。文字200%・他言語は自動回帰テストでも確認し、視力・指の操作感・母語理解を人と同等に体験したとはしない。

各実行はアプリcommit、データ版、条件ID、用件、表示言語、画面幅、開始状態、操作列、結果、画面証拠、観察した事実、想定する利用者への影響、修正、再確認を記録する。記録先は`docs/ux-evaluations/<日付>/`。人の参加者数・感想・迷った気持ちを捏造しない。AIやツールの待ち時間を人の読み取り時間として比較しない。

結果は「操作で確認できた／未完了／対象外」、問題は「画面・操作上の事実／利用者への影響の仮説」を区別する。回帰テスト、AI実操作、独立評価、人の利用者観察を混ぜない。同じAIで修正前後を試す場合、学習・既知の経路による偏りも残る。全体満足度や母集団の成功率へ換算しない。

## 改善へつなぐ

操作履歴と画面から再現できる問題をIssueへ記録し、設計のS／T／B等のIDへ対応付ける。「便利そう」等の意見だけで機能を追加しない。修正後は同じ用件で実操作と回帰テストを行い、人による確認が必要な項目を残す。[2026-10-08の結果](ux-evaluations/2026-10-08/report.md)は開発AIが実装を知って行った評価。

ペルソナ付きAIがブラウザを操作する研究例は[UXAgent](https://arxiv.org/abs/2504.09407)。一方、視覚デザインの好みで人とLLMの系統的な違いを報告した研究もある。[Distorted Perspectives](https://arxiv.org/abs/2605.18311)。本手順は早期の問題候補の発見・修正確認に使い、人の利用者検証を置き換える根拠にしない。
